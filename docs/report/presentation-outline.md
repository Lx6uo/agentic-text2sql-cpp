## 现场演示顺序

1. 提前完成 CMake 构建。运行 `./build/text2sql`，确认默认样例库已连接。
2. 无密钥时输入 `/demo`：说明回复是 Mock，SQLite 仍实际执行，最终三部门结果和两次尝试可见。
3. 已配置 API Key 时，输入“查询员工总人数，只返回总数”，展示 SQL 和查询结果区域；继续输入另一个独立问题。
4. 评测使用 `./build/text2sql benchmark`。完整数据集路径可留空；现场建议使用 `build/data/sample-spider`、2 题和新的 CSV 路径。
5. 打开 CSV（或使用 `docs/report/evidence/` 中本次保存的证据），解释 `executed` 与 `matched` 的区别；展示两种模式分别统计的题数。

## 材料口径

- 技术栈写 C++17、cJSON 1.7.19、SQLite 3.50.4、libcurl，流程写固定纠错。
- 模式名称写 Baseline 与固定纠错，CSV 中分别为 `baseline` 和 `corrected`。
- 内置包的 206 个数据库是发布包去重整合口径；原论文 200 库是论文基准口径。
- 当前展示不使用旧动态 Agent 的 20 题准确率、token、耗时或步数作为性能指标。
- 连续输入是每题独立上下文，不展示“继续筛选”作为已实现功能。
- 当前 Windows 支持有代码和构建配置，实际当前回归在 macOS 完成。
